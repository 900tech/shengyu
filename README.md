# 声屿

个人本地音频智能创作工作台。面向没有专业音频编辑基础的独立音乐人，优先服务国风 DJ、Remix 和车载音乐。音频、歌词、模板和作品都留在本机；远程侧只能走纯文本指令和状态。

安装包里的文件名使用 `Shengyu`，打开后的窗口标题和界面名称是「声屿」。这样可以避开 Windows 安装器对非英文产品名的路径问题。

## 在 Windows 上安装

构建产物由 GitHub Actions 在 `windows-latest` 上生成，用户不需要安装 Node、Python、FFmpeg 或大模型。

1. 打开本仓库的 Actions，进入「Windows 构建与冒烟」。
2. 运行成功后下载名为 `shengyu-windows` 的产物。
3. 任选其一：
   - `Shengyu-Setup-0.1.0.exe`：安装到当前用户，并创建桌面快捷方式。
   - `Shengyu-Portable-0.1.0.exe`：免安装，双击即开。
4. 安装包没有代码签名。Windows SmartScreen 可能提示发布者未知，选择仍要运行即可。不需要配置签名证书也能完成安装。

当前这次交付还不能替你把仓库推到 `github.com/900tech`。本环境的 GitHub 命令行未登录。需要你自己授权一次，步骤写在文末「让 GitHub 打出 exe」。

## 本地开发

```bash
npm install
npm start
```

`npm start` 用 Electron 打开桌面窗口。界面脚本不允许向网络发请求。

只看界面时也可以：

```bash
npm run preview
```

然后打开 [声屿预览](http://127.0.0.1:43127)。

```bash
npm test
npm run smoke
```

`npm test` 检查参数字典、清洗签名、版权拦截、白名单和版本树。`npm run smoke` 用本机 Chrome 走查关键点击，并要求控制台没有错误。

## 第一阶段验收

| 条目 | 在界面上怎么看 |
| --- | --- |
| 1.1 视觉规范 | 左侧六个入口：控制台、音频处理、模板库、作品库、远程指令、设置。浅色背景 `#F7F8FA`，主色 `#34C7BE`。设置或左下角可切换深色。没有多轨波形编辑、旋钮和推子 |
| 1.2 参数字典 | 设置 → 音频处理可看到唯一的风格、调性和版权枚举。BPM 都显示一位小数。Remix 里「±0.2 匹配」用的是同一套误差 |
| 1.3 清洗规则单源 | 在元数据清洗里取消一项。Remix 处理选项和作品库批量导出会显示同一个规则指纹 |
| 1.4 版权联动 | 模板只有自有版权、商用授权、不可商用。勾选「霜月硬鼓」后点生成，必须先确认风险，不能直接导出 |
| 1.5 版本树 | 用示例原曲生成 Remix 后，打开作品库，「月下归舟」下面会出现新版本，不用手动归类 |
| 1.6 交互规范 | 右上角「高级选项」默认收起。作品详情走右侧抽屉，风险确认走轻量弹窗。后台任务在右下角，当前 Remix 的分步进度只留在页面里 |

## 第二阶段已经能演示的部分

这些都是交互和方案，不是已经写好的音频文件。

- 控制台「查看趋势」：汽水 70%、网易云 30%，可按周或月看 BPM、调性、结构和关键词，并保存为创作模板。数据是本地样例，不会联网，也不会下载歌曲。
- 作品详情里的发行物料：汽水音乐和网易云音乐各有歌名、标签、100 字以内简介和发布时间，可以改、可以复制。
- 作品库顶部三套导出预设：汽水音乐完整版、抖音 60 秒卡点版、车载无损版。可以另存自定义预设。切换后参数跟着变。
- Remix 可多选模板，一次生成多个版本，命名为「原曲名 · 版本类型」，并挂回原曲。

## 已知 stub

- BPM、调性、风格的导入预检是占位结果，不分析音频内容。代码标记为 `TODO(engine)`。
- 人声分离、节拍对齐、自动混缩、重新封装、声学水印弱化只显示进度或方案。
- 所有导出的 `fileWritten` 都是 `false`。不会生成 mp3、wav、flac。
- 榜单不是平台抓取。
- 远程「已连接」是本机开关。没有配置外部地址，也不会发网络请求。回传只保留指令名、进度、状态和一句说明。
- 15 秒试听结束会停掉本次播放。没有导入音频时，不会伪造预览文件。

## 下一阶段从哪里接

音频引擎接在现有接口上，不要另写一套参数或清洗规则：

- `stubAnalyze(name, size)`：换成本地 BPM / 调性检测。
- Remix 分步里的「人声分离」：接本地分离模型，仍然不上传音频。
- `buildExportPlan(...)`：交给随安装包带上的 FFmpeg 写文件。写完前保持 `fileWritten: false`。
- 榜单若要更新，只拉公开文本字段，禁止下载音频。

第三阶段里，参数快照加载、指令模板、15 秒预览清理和批量操作已经有交互。真正缺的是上面的本地音频引擎。

第四阶段还没做：作品数据报表、发行日历、灵感素材库、定时任务。

## 让 GitHub 打出 exe

本环境只能把代码留在当前 Origin 仓库的 `main`。`gh` 未登录，所以不能代你推到 `github.com/900tech`，也不能在这里看到 Actions 结果。

请你：

1. 在 GitHub 新建一个空仓库，例如 `900tech/shengyu`。不要把 Cursor 的访问令牌写进仓库。
2. 把当前 `main` 推上去。
3. 打开 Actions。如果 GitHub 要求批准第一次运行，点批准。
4. 等「Windows 构建与冒烟」成功，下载 `shengyu-windows`。
5. 不需要添加签名证书。工作流里已经关闭自动签名。

工作流会先在 Ubuntu 上跑单元测试和浏览器冒烟，再在 Windows 上打包 NSIS 安装包和便携版。
